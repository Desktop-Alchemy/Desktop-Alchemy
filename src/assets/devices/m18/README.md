# M18 Visual Model

The model represents an M18 lying flat with its stand folded: width 117 mm, depth 104 mm, height 21 mm. It is based on product/reference photographs. Private reference photographs are not distributed.

`m18.glb` uses meters, +Y up and +Z toward the front; its XYZ bounding box is 117×21×104 mm. Key pitch, keycaps, display windows, corners, and bottom structures are photographic estimates for visualization/selection, not manufacturing CAD or dimensional inspection. Branding uses generic M18 text. The cable is omitted, and the rear connector/folded stand are simplified.

## Nodes and rendering budget

- `key-01`–`key-18` are separate nodes with public key numbers in `extras.key`: display keys 1–15 from top-left to bottom-right, bottom physical keys 16–18.
- `screen-01`–`screen-15` are display surfaces with `extras.screenKey`. The GLB retains plain surfaces; the app supplies the current configuration through a shared Canvas texture atlas.
- Separate light, shell, stand, foot, and connector nodes remain. A 24-color texture previews software LED settings on the strips and two top indicators; positions are approximate and do not represent hardware readback.
- Revision 2 contains 19,508 triangles, 72 mesh instances, 22 shared geometries, 10 materials, and a 237,864-byte GLB. Physical keys have a shallow continuous concavity, with edges approximately 0.45 mm above the center. The base view has 72 draw calls; custom branding adds one transparent surface. `model-info.json` contains parameters.
- Geometry is generated by `scripts/build-m18-model.mjs` without imported models or photo textures. Three.js licensing is indexed in `licenses/README.md` and included in generated previews.

## Regeneration

Run `pnpm model:m18` at the repository root to regenerate the GLB and metadata. Blender, Python, and a cloud model service are not required.

`m18-poster.png` is a transparent top-down rendering from the same client scene. In an independent Vite browser, run `scripts/render-m18-poster.js` through the repository's browser automation workflow. It refuses real Tauri WebViews. Update the poster after changing the model or scene.

`pnpm model:m18:preview` writes ignored `output/m18-model/m18-3d-preview.html`, inlining rendering code, GLB, and license. It also copies the standalone GLB/poster alongside it for offline review. The preview has rotation, zoom, 18-key selection, perspective/top/bottom views, and LED mode/brightness/speed/color controls, with no SDK or app-configuration access.

## Client lifecycle

The device list loads the static poster. The workspace defaults to top-down 3D; the page editor defaults to 2D. Both allow switching. Load the engine and GLB lazily with the 3D component; configuration and plugin images use the existing store preview interface. Rotation and selection do not trigger hardware actions or page changes.

Model branding supports default M18, 1–32 characters, or a static library image. Save per profile in `app-settings.json` with stable ImageRef values and include referenced images in backups. Missing images fall back to default branding. Branding changes only the software 2D/3D preview, not hardware or the generic home-list poster.

Static lighting draws on input, texture, or size changes. Dynamic effects update one small texture at most 20 FPS. Emissive lighting and three soft halo surfaces produce 75 typical lit draw calls without fullscreen glow, dynamic lights, or shadows. This is not physical brightness calibration. Stop animation offscreen, hidden, at zero brightness, or under reduced motion; reduced motion holds a quarter-cycle frame. Hide halos at zero brightness. Firmware effects use a static illustration. Release timers, geometry, materials, textures, environment maps, and the WebGL context on disposal or device/page change. Initialization/context failure offers retry and the outer 2D fallback.
